# 引文对象 —— 多分类任务（一键运行）

本目录是 `model/run/` 下的第三个任务入口，与 `run_sen_func`（引文情感 / 引文功能）、
`run_object`（引文对象序列标注）并列，**配置接口、运行方式、输出结构完全一致**，
只是任务换成了「引文对象多分类」，模型换成分类模型。

```
model/run/
├── run_sen_func/     # 引文情感 / 引文功能 —— 分类
├── run_object/       # 引文对象 —— 序列标注（BERT+CRF 等）
└── run_object_cls/   # 引文对象 —— 多分类（本目录，8 个分类模型）
```

---

## 1. 为什么数据要换一种形式

引文对象原始数据是给序列标注用的，文本里带片段标记：

```json
{"text": "We use the [@Semantically Conditioned Long Shortterm Memory Network (SC-LSTM)] proposed by REFLAB as our generator.", "label": "研究方法"}
```

`[@...]` 只是「对象片段在哪儿」的位置信息，标记本身不是文本内容。
而分类模型（BERT / BERT+BiLSTM / BERT+BiGRU / BERT+CNN / BiLSTM / BiGRU / CNN / RNN）
的输入格式和引文情感 / 引文功能完全一致，只认 `text` + `label`：

```json
{"text": "We use the Semantically Conditioned Long Shortterm Memory Network (SC-LSTM) proposed by REFLAB as our generator.", "label": "研究方法"}
```

所以多分类任务的第一步是把标记去掉、片段文字保留，`label` 原样不动，
样本数 / 样本顺序 / 类别分布都不变 —— 和序列标注实验是同一份数据的两种任务形式，
便于横向对照（但两边的指标含义不同，见第 6 节）。

转换由 `build_classification_dataset.py` 完成，命名规则固定：

```
dataset/<X>-引文对象.jsonl   →   dataset/<X>-引文对象多分类.jsonl
```

清洗规则（逐字符扫描，而不是正则替换）：遇到 `[@` 丢弃这两个字符并把片段深度 +1，
遇到 `]` 且深度 > 0 时丢弃并深度 -1，其余字符原样保留。
之所以不用正则，是因为源数据里有极少量畸形标记，正则单遍替换会留残渣：

- **嵌套**：`[@global [@beam-search parsers]#O*]` —— 正则会把前一个 `[@` 到第一个 `]` 当成一个片段，
  替换后内层的 `[@` 留在文本里；
- **未闭合**：`... washing buffer [@50 mM Tris HCl, ...`（后面没有 `]`）—— 正则匹配不到，`[@` 原样留下。

4 个数据集里这样的样本各 1 条（共 3 条），扫描法与正则法只在它们身上不同，
其余 42033 条逐字节一致；转换后 4 个数据集都**不含** `[@` 残留。

现有 4 个数据集（转换后样本数不变）：

| 数据集 | 样本数 | 其他 | 研究方法 | 研究问题 | 数据 |
|---|---|---|---|---|---|
| SDCF-引文对象 | 14271 | 5903 | 2805 | 5470 | 93 |
| ACL-W-引文对象 | 5341 | 2113 | 2517 | 246 | 465 |
| ACTSCI-引文对象 | 9568 | 4791 | 2280 | 2072 | 425 |
| ICLR-引文对象 | 12856 | 5416 | 4362 | 2124 | 954 |

> 一键运行时若数据集不存在会**自动转换**，不用手动先跑转换脚本。

## 2. 目录与文件

```
model/run/run_object_cls/
├── config.py                        # 数据集组合、模型清单、比例、输出路径
├── build_classification_dataset.py  # 序列标注数据 → 多分类数据（批量/单文件）
├── run_all_models.py                # 一键运行（自动转换数据 → 跑模型 → 自动汇总）
├── summarize_results.py             # 单独汇总，生成 model_comparison.csv
└── 说明.md                          # 本文件
```

模型直接复用 `model/` 下已有的 8 个分类脚本，**没有复制、没有改模型代码**：

| 模型 | 脚本 |
|---|---|
| BERT | `model/BERT/bert.py` |
| BERT+BiLSTM | `model/BERT+BiLSTM/bert_bilstm.py` |
| BERT+BiGRU | `model/BERT+BiGRU/bert_bigru.py` |
| BERT+CNN | `model/BERT+CNN/bert_cnn.py` |
| BiLSTM | `model/BiLSTM/bilstm.py` |
| BiGRU | `model/BiGRU/bigru.py` |
| CNN | `model/CNN/cnn.py` |
| RNN | `model/RNN/rnn.py` |

> CRF 系列（BERT+CRF、BiLSTM+CRF 等）是序列标注模型，不能用于多分类，不要加到本目录的 `MODELS` 里。

## 3. 配置（config.py）

和 `run_object` 完全相同的三项配置：

```python
DATASET_METHOD = 3          # 1=单数据集按比例划分；2=训练/测试分别指定；3=N*N 批量训练
TRAIN_RATIO = 0.8           # 方法2/3 下，训练集数据集使用多少
TEST_RATIO = 0.2            # 方法2/3 下，测试集数据集使用多少

TRAIN_DATASETS = {          # 自定义名 → 实际路径（多分类格式）
    "SDCF-引文对象多分类": os.path.join(BASE_DIR, "dataset", "SDCF-引文对象多分类.jsonl"),
    ...
}
TEST_DATASETS = { ... }     # 同上
MODELS = [ ... ]            # 8 个分类模型
```

- `DATASET_METHOD = 3` 时按「4 个训练集 × 4 个测试集 = 16 个组合」批量跑，
  正好对应 `说明-ynt` 里引文对象的跨领域 / 跨数据集实验。
- 只想快速验一个组合时，把 `TRAIN_DATASETS` / `TEST_DATASETS` 里注释到各剩一个即可。
- 比例与 `run_object`（序列标注）保持一致（0.8 / 0.2），方便两边对照。

## 4. 一键运行

```bash
cd model/run/run_object_cls
python run_all_models.py
```

流程：**检查/自动生成多分类数据集 → 按组合逐个跑模型 → 回收结果 → 自动汇总**。

常用参数：

```bash
python run_all_models.py --list                     # 只看会跑哪些组合和模型
python run_all_models.py --models RNN,CNN           # 只跑指定模型（试跑/排查用）
python run_all_models.py --output-root D:/tmp/试跑   # 结果写到别处，不污染正式目录
python run_all_models.py --skip-build               # 不自动生成数据集
python run_all_models.py --skip-summary             # 只跑模型，不汇总
```

单独执行某一步：

```bash
python build_classification_dataset.py --stats   # 只做数据转换，并打印类别/长度统计
python summarize_results.py                      # 只汇总（模型已跑完时）
```

## 5. 输出结构

与 `run_sen_func`、`run_object` 保持一致的目录习惯，结果根目录用任务名区分：

```
传统模型-服务器用/
├── 引文情感/            # run_sen_func 的结果（历史）
├── 引文对象/            # run_object 的结果（历史）
└── 引文对象多分类/       # 本任务的结果
    ├── <训练集名>-<测试集名>/        # 方法2/3；方法1 为 <数据集名>
    │   ├── BERT/
    │   │   ├── output.log
    │   │   ├── predictions_vs_true.csv     # 样本序号, 真实标签, 预测标签
    │   │   └── classification_results.csv  # 类别, 精确率, 召回率, F1分数, 支持数
    │   ├── BiLSTM/  BiGRU/  CNN/  RNN/
    │   ├── BERT+BiLSTM/  BERT+BiGRU/  BERT+CNN/
    │   └── model_comparison.csv   # 方法1：该数据集自己的汇总长表
    ├── model_comparison.csv               # 方法2/3：全局汇总长表
    └── model_comparison_all_datasets.csv  # 跨数据集总表（--all-datasets 生成）
```

`model_comparison.csv` 是长表，每次「数据集组合 × 模型」一行：

```
训练集,测试集,模型名称,整体准确率,加权平均精确率,加权平均召回率,加权平均F1分数,其他_精确率,...,其他_支持数,...
```

跑 N*N 时按「训练集-测试集」筛选，就是每种跨数据集组合的加权 F1（`说明-ynt` 要统计的那个值）。
终端还会额外打印两张表：各组合下的模型排名、每个模型在全部组合上的平均加权 F1。

### 分数据集补充实验（4 数据集 × 8 模型）怎么汇总

方法1 一次只跑一个数据集，汇总文件放在**各自数据集目录**里，所以换数据集不会互相覆盖：

```
引文对象多分类/ICLR-引文对象多分类/model_comparison.csv   ← 只含 ICLR 的 8 个模型
引文对象多分类/SDCF-引文对象多分类/model_comparison.csv   ← 只含 SDCF 的 8 个模型
...
```

4 个数据集都跑完后，生成一张「模型 × 数据集」的横向总表：

```bash
python summarize_results.py --all-datasets
```

输出 `引文对象多分类/model_comparison_all_datasets.csv`（数据集, 模型名称, 整体准确率, 加权F1, 各类别指标...），
并在终端打印以「模型为行、数据集为列」的加权 F1 透视表——这张表就是补充实验要的结果表。

## 6. 注意事项

1. **与序列标注实验的指标不可直接比数值**：序列标注算的是 span 级 P/R/F1（片段边界对不对），
   多分类算的是「整条文本的对象类别对不对」。多片段样本在源数据里只有一个 `label`，
   所有 `[@...]` 片段共享这个类别（原序列标注脚本也是这么标 BIO 的），
   所以本任务衡量的是整句的对象类别，用于任务形式对照，不能和 CRF 的 span F1 对齐比较。
2. **类别不均衡**：`数据` 类最少（SDCF 只有 93 条，占 0.65%），
   整体准确率会被 `其他` 主导，建议以加权平均 F1 + 逐类 F1 为准。
3. **文本长度 vs max_len**：ICLR 文本中位长度 565 字符，而 `BERT/bert.py` 的 `max_len = 128`
   （其余 7 个模型是 256）。这是沿用引文情感 / 引文功能的统一超参，未改动；
   若想让 BERT 在这批数据上更公平，需改 `model/BERT/bert.py` 超参区（会影响所有任务）。
4. **预训练模型路径**：`model/*/*.py` 里写的是服务器路径
   `/root/autodl-tmp/model/bert-base-cased`，本地跑需要改成自己的路径
   （如 `E:\MODEL\bert-base-cased`）；服务器上按 `说明-ynt` 用 modelscope 下好即可。
5. **PYTHONPATH**：模型脚本需要从本目录的 `config.py` 读 `TRAIN_RATIO` / `TEST_RATIO`，
   `run_all_models.py` 用 `os.pathsep` 拼接（Windows `;`、Linux `:`），服务器上也生效。
